# IMPLEMENTATION TASK: SaaS Excel to RDB Import Service (Spring Boot)

## 0) Goal
Generate a runnable Spring Boot 3.2.x + Java 17 project that implements the API and data model described in the SPEC section.
The project must run locally using Docker Compose (PostgreSQL + Redis) and store uploaded files on local filesystem (as NFS substitute), configurable by property.

Deliverables:
- Full Maven project under `pr/` (or repository root)
- `docker-compose.yml` for postgres + redis
- DB migration (Flyway recommended)

## 1) SPEC (source of truth)
### Overview
- Upload Excel file (xlsx/csv) -> validate -> load into RDB (PostgreSQL/MySQL)
- Tech: Spring Boot 3.2.x, Redis Session, Tomcat (stateless), file storage on NFS (shared disk)
- Async job-based processing

### Architecture
- Stateless API with Redis session
- DB: PostgreSQL (default), MySQL optional
- Storage: NFS (implement as local folder path; assume shared disk)

### Database ERD
Tables:
1) import_job
- id (UUID, PK)
- tenant_id (UUID)
- status (ENUM: CREATED, PARSING, VALIDATING, LOADING, COMPLETED, FAILED)
- file_uri (TEXT)
- total_rows (INT)
- success_count (INT)
- fail_count (INT)
- error_log_uri (TEXT)  // optional file path for aggregated report
- created_at, started_at, finished_at (TIMESTAMP)

2) excel_data
- id (UUID, PK)
- job_id (UUID, FK -> import_job.id)
- col_1..col_n (TEXT)  // store dynamic columns as JSONB recommended, but can be col_1..col_20 for MVP
- created_at (TIMESTAMP)

3) error_log
- id (UUID, PK)
- job_id (UUID, FK)
- row_index (INT)
- column_name (VARCHAR)
- error_code (VARCHAR)
- error_msg (TEXT)
- created_at (TIMESTAMP)

### API
Base: /api/v1

1) POST /imports
- multipart/form-data
- file (xlsx or csv)
- tenant_id (UUID)
Response: 201
{
  "success": true,
  "data": { "jobId": "uuid" },
  "meta": { "requestId": "...", "timestamp": "..." }
}

2) GET /imports/{jobId}
Response: 200
{
  "success": true,
  "data": {
    "jobId": "uuid",
    "status": "VALIDATING",
    "progressPct": 52,
    "totalRows": 1200,
    "processedRows": 600
  }
}

3) GET /imports/{jobId}/errors
- Return validation failures with pagination:
  - query params: page (0..), size (default 50), sort (created_at desc)
Response: 200
{
  "success": true,
  "data": {
    "items": [ ... ],
    "page": 0,
    "size": 50,
    "totalElements": 120,
    "totalPages": 3
  }
}

### HTTP status codes
- 201: Created (job created)
- 400: missing file/tenant_id invalid
- 415: unsupported format
- 404: job not found
- 422: validation errors exist (NOTE: job can still complete with partial failures; do not block completion)
- 5xx: server errors

### Error format
Use RFC7807 `application/problem+json`:
{
  "type": "...",
  "title": "...",
  "status": 422,
  "detail": "...",
  "instance": "...",
  "errors": [ { "rowIndex": 12, "column": "email", "code": "INVALID_FORMAT", "message": "..." } ],
  "requestId": "..."
}

### Validation & Error Codes (examples)
- IMP-FIL-001: INVALID_EXTENSION
- IMP-PAR-001: HEADER_MISMATCH
- IMP-VAL-001: REQUIRED_FIELD

### File Storage Policy
- Save original xlsx as-is (no additional compression)
- Allow compression for CSV only (optional for MVP; can skip)
- Save to NFS with checksum-based path:
  /{storageRoot}/{tenantId}/{sha256_prefix}/{sha256}.{ext}
- Retain TTL: configurable (default 30 days). For MVP implement only the property; actual cleanup job optional.

### Implementation Notes
- Excel parser: Apache POI streaming (SXSSF when writing; for reading large XLSX use XSSF event model or keep simple for MVP)
- Async worker: @Async executor
- DB batch: JPA batch for MVP

## 2) Implementation constraints / MVP decisions
To ensure a working MVP, implement these decisions:
- Support XLSX and CSV
- For excel_data storage:
  - Use `payload_json` column (PostgreSQL JSONB) to store row data dynamically.
  - If MySQL, use JSON type. Provide Postgres migration first.
- Validation rules for MVP:
  - Column A must not be empty (example: `col_1` required)
  - Max length for any cell: 255 chars
- Partial success allowed:
  - If some rows fail validation, log into error_log and continue loading valid rows.
- Progress:
  - totalRows, processedRows tracked
  - progressPct = floor(processedRows / totalRows * 100)
- RequestId:
  - Generate per request (UUID) and include in response meta / problem response.

## 3) Project structure requirements
- Package base: `com.example.excelimport`
- Use controller/service/repository layering (OOP, cohesive naming)
- Provide these main components:
  - controller: `ImportController`
  - service: `ImportJobService`, `ImportWorkerService`

  - error handling: `GlobalExceptionHandler` producing RFC7807
  - entities + repositories: `ImportJob`, `ExcelRowData`, `ImportErrorLog`
  - async config: `AsyncConfig`
  - response wrapper: `ApiResponse<T>` with meta
